# 3. 보고 — 개명으로 같은 글자가 셋 선다

설계가 「화면에서 헷갈리면 보고해 달라」고 한 자리다. **헷갈린다.**

| 무엇 | 화면 글자 |
|---|---|
| 팔레트 **탭** | 기초 가공 · 복합 가공 |
| 노드 (`proc`) | **가공** |
| 노드 (`muni`) | **기초 가공** |
| 노드 (`munix`) | **복합 가공** |

즉 **탭 「기초 가공」을 누르면 그 안에 「가공」과 「기초 가공」이 나란히** 있고,
**탭 이름과 노드 이름이 같은 글자**다. 고르는 순간에는 둘 다 「가공」으로 읽힌다.

📌 **값이 아니라 이름이라 구현이 정하지 않는다** — 고르는 것은 설계·사용자다. 후보만 적는다.
- 탭 이름을 바꾼다(예: 「가공 1단」 · 「가공 2단」처럼 층을 드러내는 말)
- 노드 이름을 바꾼다(예: `proc` 를 「소재 가공」처럼 무엇을 만드는지로)
- 그대로 둔다 — 탭과 노드는 자리가 달라 실제로는 안 헷갈릴 수도 있다(육안으로 판정)

# 4. 물음 다섯 — 코드에서 본 사실만

## 4-1. 태그 오토 스위치 기본값 — **꺼짐**

`TagAutoMode.DefaultEnabled = false` (`PlayerPrefs` 키 `mbi.tag.auto`).
러너가 매 틱 그 값을 시뮬에 넣는다. ⚠️ 시뮬 자체의 기본값(`AutoTagEnabled`)은 `true` 지만
**러너가 덮으므로 화면 기준은 꺼짐**이다. 값은 안 건드렸다.

**자동 교대 트리거**(같이 묻기에 함께 적는다) —
- **주 = 대기 로봇의 마운트 만충** (「만재 등장」 · 태그 스킬이 여기서 나간다)
- **보조 = 활성 로봇의 마운트 소진** (약한 등장)
- 둘이 동시에 성립하면 **만충이 이긴다**
- 전역 쿨다운 **5초**(`TagSystem.CooldownSeconds`) — 수동 태그 진동 방지 안전장치

📌 코드에 **「태그 주기 10초」를 목표로 쓰는 자리는 없다**(설계가 물은 것). 파생값 그대로다.

## 4-2. 태그 스킬 판정 — **화면 안의 살아 있는 적 전부**

방향을 안 본다. `foreach (적) if (살아 있고 화면 안) 표적에 넣는다`.
📌 피해는 **전부에 같은 값**이다(구현 가정 · `260908_V05` 판정 요청 그대로 남아 있다).
⚠️ 연출은 「적 무리 방향 한 번」이라 **판정이 연출보다 넓다** — 설계가 우려한 자리가 맞다.

## 4-3. 스폰 띠 8 — **로봇 중심 반경 8~14 · 단위는 월드 유닛 = 보드 한 칸**

- 값: `spawnRingMinTbd 8` · `spawnRingMaxTbd 14`(`CombatTuning.asset`)
- **화면 가장자리에서 안쪽으로의 폭이 아니다** — 화면과 무관하게 **로봇을 중심으로 한 거리**다.
- 단위는 월드 유닛이고, 보드 한 칸이 **1 유닛**이므로(`BoardConfig.cellSize = 1`) **칸 수와 같다**.
- **측정법** — 적이 날 때 `SpawnDistance(index)` 가 8~14 를 황금비 계단으로 훑어 거리를 고르고,
  `SpawnRingRule.Position(로봇 자리, …, 그 거리)` 가 **로봇 자리 + 방향 × 거리**로 놓는다.
  디스폰 되돌림은 **띠의 바깥(14)** 을 쓴다.

## 4-4. 로봇 A 포트 좌표 규약

| 항목 | 코드 |
|---|---|
| 원점 | 격자 **(0,0) 칸의 왼쪽 아래**(`BoardGrid.Origin`) |
| y 방향 | **위로 커진다** — `CellToWorld` 가 `Origin.y + (cell.y + 0.5) × 칸` |
| A 포트 | **(1,4) 남쪽 면** (`PartLayout.Mounts`) |
| 도착 칸 | **(1,3)** — 포트의 남쪽이 곧 그 칸이다 |
| 마운트 그림·적재 열 | **x = 1 · y 0~3**(`MountDisplay.RobotAColumn = 1`) — **격자 안**이다 |

⚠️ **설계가 문서에 적은 「마운트 칸 x−1 × y5~8」은 낡은 판이다**(§72-6 이전).
지금은 격자 **안**의 x1 · y0~3 이고, 포트도 (1,4) 남면으로 내려왔다. **정정을 청한다.**

## 4-5. 광역형 드론의 광역 판정 반경 — **값이 없다**

**따로 있는 값이 아니다.** 광역 타격은 지금 **드론 사거리**를 반경으로 쓴다 —
`(적 자리 − 드론 자리)² > d.AttackRange²` 이면 건너뛴다.
그 사거리는 `RobotSetup.droneAttackRange` 이고 러너가 `tuning.robotAttackRangeTbd` = **9.2** 를 넣는다
(본체와 같게 둔다 · C-3 확정).

⚠️⚠️ **그러니까 09-16 에 고친 것은 그림뿐이었다.** 「사거리를 반경 칸에 넣지 않는다」는
**판정에는 아직 안 걸려 있다** — 판정이 곧 사거리를 반경으로 쓰고 있다.
📌 **값은 설계 몫이라 안 지어냈다.** 사는 자리를 만들어 두었으니(5장) 값만 주면 된다.

# 5. 광역형 범위 이펙트 — 붙였고 **기본은 안 그린다**

| 무엇 | 어떻게 |
|---|---|
| 자산 자리 | `CombatTuning.droneAoeSprite` — **아트가 오면 그쪽이 이긴다** |
| 자리표시 | `PlaceholderSprite.Ring()` — **속이 빈 얇은 고리**(테두리 두께 = 반지름의 6%) |
| 크기 | **판정이 실제로 쓴 반경**(`ShotEvent.aoeJudgeRadius`) · 지름 = 반경 × 2 |
| 층 | 바닥에 퍼지는 것이라 **액터보다 아래**(그림자와 같은 결) |

⚠️⚠️ **폭발탄 칸(`aoeRadius`)을 다시 쓰지 않았다.** 그 칸은 **속이 찬 사각**으로 그려지고,
09-16 에 거기에 사거리를 넣어 한 변 18.4 짜리 주황 사각이 화면 절반을 덮었다.
**제 칸을 새로 만들어** 광역형일 때만 싣는다.

📌 **자리표시를 기본으로 켜지 않은 까닭** — 4-5 때문이다. 지금 켜면 **반경 9.2 짜리 고리**가 뜬다.
속이 빈 고리라 덜 가리지만 같은 수다. 판정 반경 값이 오면 그때 켠다.
⚠️ **그림이 판정과 다른 수를 그리지 않게** 했다 — 보기 좋으라고 작은 원을 그리면
화면이 거짓말을 한다. 그래서 「작게 그려 켜 두기」를 고르지 않았다.
