**열을 갈랐다.**

| 열 | 누적형 | 광역형 | 뜻 |

# 5. 리허설 1 — 둘

## 5-1. 조립 화면 인셋 카메라 (`5c66915`)

**실측** — 인셋은 가로 전체·세로 30% 뷰포트라 가로세로비가 주 카메라의 **3.33배**다.

| | 주 카메라 | 인셋(종전) |
|---|---|---|
| 가로 반폭 | **4.5 칸** | **15 칸** (전폭 30) |
| 스폰 띠 | 로봇 기준 **8~14 칸** | **통째로 들어 있었다** |

**규칙** — 인셋 가로 반폭을 주 카메라와 같게 한다.

```
인셋비 = 주비 ÷ HeightShare   ⇒   인셋ortho = 주ortho × HeightShare
```

📌 **가로세로비가 식에서 지워진다** — 창을 재지 않아도 되고 어떤 화면비에서도 두 화면의
가로 폭이 같다. **지어낸 수가 하나도 없다**(쓰는 것은 `HeightShare` 하나).

⚠️ 세로는 8 → 2.4 로 좁아진다. 그것이 「줌인」의 내용이다. 모서리까지가 √(4.5²+2.4²) ≈ **5.1 칸**
이라 띠 최솟값 8 안쪽 — 갓 스폰한 적은 안 보이고 **걸어 들어오면서** 보인다.

🗑️ `BackgroundHalfWidth` 의 넓히기(3.33배) 폐기 — 인셋이 더 넓게 보던 시절의 식이다.

## 5-2. 멀리 서서 안 오는 몬스터 (`105fad7`) — **결함이 아니다. 규칙이다**

**계획 세션**이 준 다섯 갈래 중 **길막 적층**이 답이다.

| 실측(S1~S5 전 표본) | 값 |
|---|---|
| **「안 막혔는데 정지」** | **0** |
| 굳음의 정체 | **100% 길막**(밀어내지 않음·막히면 멈춤 = 사용자 확정 사양) |
| 포격 | **굳음 0** — 전부 「사거리 안」. 사거리 7 에서 **서서 쏘는 것이 규칙**이다 |
| 굳는 종 | 전부 보병 · 가장 먼 굳음 **20~30칸** |

사용자 스크린샷의 「멀리 정지한 여섯」 중 **일부는 포격이 제 사거리에서 쏘고 있는 것**이고

⚠️ `GridMovement.IsBlocked` 는 **순수 함수**라 시뮬을 안 흔들고 물어볼 수 있다
(`StepOrSide` 는 붙들기 상태를 고쳐 쓰므로 프로브가 부르면 안 된다).

### 설계 판정 거리 하나 — **값을 안 지었다**

되돌림 문턱이 `이동 속도 × 20초` 이고 보병 이동 1.5 라 **30칸**이다. 그런데 잣대는
「닿을 수 있는가」인데 재는 것은 **명목 속도**다 — **막혀서 실제 0칸/초인 적도
「20초면 닿는다」로 계산돼 영영 안 걷힌다.**
20초는 사용자 확정(§71-27)이고 「링 반경 × N」의 N 은 미정이므로,
**잣대를 실제 이동량으로 바꿀지**는 설계가 정할 일이다.
