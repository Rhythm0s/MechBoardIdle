## 2-1. 얹은 줄의 모양 — **A 와 B 가 다르다**

레시피 차례는 문서대로다: **가공(발전재료) → 기초 군수(추진제) → 부스터 둘.**
자리는 구현 판단인데, **같은 모양을 두 판에 못 쓴다** — A 는 합류 기둥(x=8)과
운반로(y=5)가, B 는 어깨L(x≥9)이 이미 차 있어 **남는 자리가 다르다.**
노드 수 · 레시피 · 부스터 대수는 **둘이 같다.**

| | 로봇 A | 로봇 B |
|---|---|---|
| 코어 쓰는 면 | **북** | **서** |
| 줄 | 벨(5,9) → 가공(6,9) → 벨(7,9) → 군수(8,9) → 분류기(9,9) | 벨(4,8)(4,7)(4,6) → 가공(5,6) → 군수(6,6) → 분류기(7,6) |
| 부스터 | (10,9) · **(9,10) 회전 3**(서면 → 남면) | (8,6) · 벨(7,5) → (8,5) |

**에너지 노드는 더 놓지 않았다**(설계가 물은 것). 근거는 산수가 아니라 실측이다 —
**전력 효율이 세 판 모두 1.000** 이다. 에너지 셋이 공급 30 이고 줄이 더 먹는 것은
가공 1 + 기초 군수 2 + 부스터 2×2 = **7** 이다.

⚠️ **첫 배치는 끊겨 있었다.** 분류기 서쪽에 벨트를 한 칸 두었더니
`BeltAutoOrient` 가 **북쪽 벨트를 입력면으로 뽑아** 추진제가 거꾸로 흘렀고,
부스터가 집계에 **0 대**로 잡혔다. **분류기는 군수 노드에 딱 붙여야 한다** —
자동 배향이 노드를 먼저 보기 때문이다. 시험(`HarnessBoosterLineTests`)이 잡았다.
📌 **내가 적은 면은 남지 않는다** — 자리로 말해야 한다.

# 6. 조립 문서 09-17 개정과 코드 대조 — 어긋난 자리 **하나**

넷을 봤다: **면 스냅(3장) · 화살표 규칙(9-2) · 보드 저장 장 · 11-7.**
**화살표 규칙 셋과 11-7 은 코드와 같다** — 고칠 것이 없다.
면 스냅도 같다(끝 칸 둘일 때 **드래그 마지막 방향 앞 면** 우선 · 「면이 다름」 경고 있음).

## 6-1. ⚠️⚠️ **보드 저장 규칙 5 가 B 판에서는 안 섰다 — 구현 결함이었다**

문서: 「저장은 **보드마다 따로** 한다」(11-7) + 「**시작 보드 세대**를 같이 싣고,
다르면 버린다」(규칙 5).

코드: 세대 표식을 만들 때도 견줄 때도 **`StartingBoard.Generation` 하나**를 썼다.
그런데 **시작 보드는 이제 둘**이고 `StartingBoardB` 에는 **표식 자체가 없었다.**

📌 **그래서 `StartingBoardB` 를 고치면 B 의 저장이 안 버려졌다.** 세대가 안 바뀌고
크기(12×14)도 주인도 같으므로 **옛 B 판이 새 B 시작 보드 위에 조용히 올라온다** —
09-15 에 A 에서 났던 그 사고와 **같은 모양**이고, 그때는 화면에 「벨트를 이었는데
마운트 적재 0」으로 보였다.

✅ **사용자 결정(2026-09-17) — 고친다.** B 저장 1회 소실을 감수한다(규칙 #22 이행 ·
부스터 줄 배포 전 필수). **이행 완료** — `BoardGeneration`(신설)이 셈을 한 자리에 모으고,
`StartingBoardB.Generation` 을 새로 두었으며, 저장을 **뜰 때도 견줄 때도 주인의 판**을 본다.
시험 아홉이 붙었다(`BoardGenerationTests`).

📌 **`BoardStateV1` 에 필드를 새로 안 넣었다** — 이미 `generation` 과 `owner` 를 싣고
있어서 고칠 것은 **찍는 값과 견주는 값의 출처**뿐이었다. 필드를 하나 더 두면 같은 것이
두 곳에 사는 자리가 된다(지침 §7).
📌 **A 의 표식은 안 바뀐다** — 이 개정이 하기로 한 일은 B 하나이므로, A 판은 조합표를
안 섞어 옛 셈과 **바이트가 같다**(시험 `A_표식은_이_개정으로_안_바뀐다` 가 못 박는다).
B 는 조합표를 섞는다 — 가공 셋이 같은 자산이고 조합표만 다르다.
📌 **곁가지 하나** — 표식이 주인별이 되면서 「남의 판」은 세대도 함께 어긋난다.
그래서 `WhyNotFit` 이 **주인을 세대보다 먼저** 보게 했다. 둘 다 참이지만
「주인이 다르다」가 고칠 자리를 가리킨다(기존 시험 `남의_판은_안_푼다` 가 그 자리를 짚어 줬다).

⚠️⚠️ **대가 — 지금 있던 B 저장이 한 번 버려졌다.** 표식이 바뀌면 그 자체로 세대가
안 맞으므로, 규칙 5 가 제 일을 해서 복원을 거른다. 즉 **고치는 대가가 곧 규칙 5 가
하기로 한 일**이다. 「저장이 사라지는 것은 감수한다」는 사용자 확정이고
(보드 저장 규칙 5 · 플랜 §74-3 #22), **이번에도 유효한지를 사용자가 확인해 주었다.**

# 8. 구현 오류 기록 — 오늘 하나

**분류기를 노드에서 한 칸 띄웠다.** `BeltAutoOrient` 가 분류기 입력면을
**이웃에서 다시 잡는데**, 노드를 먼저 보고 없으면 **면 차례대로 아무 벨트나** 고른다.
분류기 서쪽에 벨트를 한 칸 두었더니 **북쪽 벨트가 입력면으로 뽑혀** 추진제가 거꾸로
흘렀고, 부스터가 집계에 **0 대**로 잡혔다.

📌 **내가 적은 면은 남지 않는다 — 자리로 말해야 한다.** 이것은 09-11 에 병합기가
같은 자리에서 겪은 일(「첫 배치가 통째로 끊겼다」)의 **재발**이다.

⚠️ **시험이 잡았다.** 「줄이 다 놓인다」만 봤으면 못 잡았을 것이다 —
**놓였는지가 아니라 집계에 잡히는지**를 본 시험(`A_판이_부스터_둘과_추진제를_집계에_낸다`)이
`Expected: 2 / But was: 0` 으로 걸렀다. 그 시험이 없었으면 나 판이 가 판과 같은 수를
내고 나는 그것을 **「부스터를 놓아도 안 변한다」로 보고**했을 것이다.
