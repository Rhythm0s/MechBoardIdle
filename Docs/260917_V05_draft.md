# 3. 쉴드 배포 (`260917_W07` 4장)

## 3-1. 시작 보드 A · B — 칸은 모자라지 않았다

**빈 칸을 먼저 셌다**(짐작하지 않으려고 `FreeCellProbe` 를 만들었다) — 놓은 뒤에도
A 84칸 · B 90칸이 남는다. 둘 다 **가공 1 · 기초 군수 1 · 발생 1 + 벨트 3 = 여섯 칸**이다.

| 판 | 쓰는 코어 면 | 자리 |
|---|---|---|
| **A** | **서면** | 벨(4,8) → (4,7) → (4,6) → 가공(5,6) → 군수(6,6) 방어 재료 → **쉴드(7,6)** |
| **B** | **북면** | 벨(5,9) → 가공(6,9) → 군수(7,9) 방어 재료 → **쉴드(8,9)** |

⚠️ **A 와 B 의 자리가 다르다** — B 의 서면은 **추진제 줄이 이미 쓴다**. 남은 면을 골랐다.
📌 **가공은 표준탄 줄과 안 나눠 쓴다**(사용자 확정). 대가는 **전력**으로 낸다(수요 14.0 → 17.0).
⚠️ 자리는 **구현 판단**이다 — 역기입 자리.

## 3-2. 저장이 버려지는 것 — 까닭이 판마다 적힌다

세대 표식이 A · B 둘 다 바뀌었다. 저장을 버릴 때 로그가 남는데, 그 까닭 문자열이
**어느 판인지를 포함**한다(`시작 보드 세대가 다르다(RobotA)`). 시험이 A · B 양쪽을 본다.
⚠️ 한 줄로 뭉치면 **무엇이 버려졌는지** 못 읽는다 — 그래서 판 이름을 본다.

## 3-3. 팔레트 — 여덟이 됐다

쉴드 발생을 넣어 **여덟 칸**이다. 탭은 안 만들었다 — `PaletteCategories.Of` 가
**입력면 수**로 가르고 쉴드는 입력면 하나라 **기초** 탭으로 자동으로 간다.

⚠️ **한 가지 어긋남을 보고한다** — **부스터는 「전력」 탭에 명시로 박혀 있다**.
쉴드는 규칙(입력면 수)대로 가면 **기초**다. 생존 두 층이 **다른 탭**에 서게 된다.
설계가 「입력면 수로 갈린다」고 적어 준 대로 두었으나, 부스터와 나란히 두고 싶다면
`PaletteCategories.Of` 의 명시 그룹에 한 줄을 더하면 된다 — **판정 요청**으로 올린다.

## 3-4. HUD 쉴드 게이지 — **규격이 문서에 없었다**

UI 문서 · UI 아트 요청 문서를 찾았다. **쉴드 게이지 규격이 없다** —
있는 것은 회피 스택의 「HP 바 인접」뿐이다. 설계 지시대로 **HP 규칙을 그대로** 썼다.

|---|---|
| HUD 글자 줄 | `로봇 HP 692/1000` **바로 뒤**에 `쉴드 120/200` — HP 와 같은 「현재/최대」 서식 |
| 로봇 머리 위 | HP 바 **바로 위 한 칸**. 같은 너비 · 같은 높이 · 같은 「왼쪽에 붙여 줄인다」. 색만 청록 |
| 합체 중 | **두 보드 게이지를 합산**해 보인다 — `쉴드(합산) 240/400` |
| 쉴드가 없는 판 | 글자 줄은 **빈 문자열** · 막대는 **사라진다**(없는 층을 0/0 으로 그리면 고장으로 읽힌다) |

발생 노드가 빠지면 그 줄의 **가공·군수가 낼 곳을 잃어 일감률이 떨어지고**, 그 몫까지 같이 준다.
📌 대당 값의 합(가공 1 + 군수 2 + 발생 1 = 4)으로 적으면 **안 맞는다** — 그 수는 일감률 1 일 때의 값이다.

**③ 회피 횟수는 세 판이 같다(31회).** 이동이 붙어도 **발동 횟수는 안 변한다** —
